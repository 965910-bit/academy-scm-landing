# Академия SCM — учебная платформа

## Запуск кабинетов

Кабинеты требуют Node.js с `node:sqlite` и постоянного диска. Проверено на
Node 22.22.3. Обычный статический сервер не предоставляет авторизацию.

Из корня репозитория:

```sh
npm ci --prefix academy
DATA_DIR=/secure/academy-data node server/server.cjs bootstrap "Фамилия Имя Отчество"
PUBLIC_ORIGIN=https://ваш-домен DATA_DIR=/secure/academy-data PORT=4173 node server/server.cjs
```

Откройте `/academy/`. Вход — ФИО и пароль, без выбора роли.
Bootstrap выводит временный пароль один раз оператору; замените его при первом
входе. Готового пароля администратора в репозитории нет. Повторный bootstrap
при существующем администраторе отклоняется. Используйте защищённый терминал,
не публикуйте его вывод. По умолчанию cookie требует HTTPS.
`COOKIE_SECURE=0` — исключительно локальное HTTP-тестирование.

## Роли

- Администратор создаёт аккаунты всех ролей, сбрасывает пароли, блокирует
  неадминистративные аккаунты и открывает любое рабочее пространство через свою
  сессию. Пароли владельцев при открытии не меняются; действие журналируется.
- Приёмная комиссия создаёт и обслуживает только абитуриентов и слушателей.
  Она не выдаёт административные полномочия и не открывает чужие пространства.
- Абитуриент, слушатель, преподаватель и работодатель входят каждый под своей
  учётной записью и получают свой набор экранов и своё рабочее пространство.

Сгенерированный пароль виден один раз, хранится как scrypt-хеш и подлежит
обязательной замене. После сброса/блокировки прежние сессии прекращаются.
Совпадающие нормализованные ФИО запрещены: нужен согласованный различимый вариант.

## Что уже доступно

Семь подготовительных образовательных направлений, учебные модули, лаборатория
запасов, практикум решений, планировщик, критерии и история проверки,
база первоисточников, открытая библиотека и каталог 54 форм документов.
Публичная проверка выданных документов — `/registry/registry.html`,
подтверждённых выдач в рабочем наборе пока нет.

Лицензирование, фактический приём, платёж, юридически значимое подписание,
государственный студенческий и ФРДО не включаются наличием аккаунта.
Карточки программ и документов сохраняют эти ограничения.

## Границы совместной работы

Сервер хранит отдельный JSON-workspace на аккаунт с проверкой ревизии.
Внутренние учебные профили/группы старых модулей — не аккаунты и не способ входа.
Пока нет общей организационной очереди работ между аккаунтами преподавателя
и слушателя, глобальных заявлений приёмной комиссии или публикации общих
программ из workspace в публичный каталог. Следующий этап — адресные процессы
на сервере с предметными правами, а не раскрытие всем чужих данных.

Старый общий localStorage не импортируется в аккаунты автоматически:
у прежних записей не установлен владелец. Не переносите его целиком первому
пользователю. Реальные документы и чувствительные сведения требуют отдельной
защищённой системы хранения и правовой проверки.

## Офлайн и сохранение

Пакет v10 содержит только публичную оболочку, статьи и аннотации. API-ответы,
пароли и приватные workspace не входят в service worker. Для входа, загрузки
кабинета и сохранения требуется сеть. При обрыве текущая работа остаётся
в памяти вкладки; серверная ошибка видна, доступен экспорт. Не закрывайте
вкладку до сохранения или экспорта. Приватная офлайн-синхронизация пока не реализована.

## Тесты

```sh
npm test --prefix academy
CHROMIUM_PATH=/path/to/chromium npm run test:browser --prefix academy
```

74 автоматических теста, включая реальные HTTP-проверки ролей, изоляции,
сессий, нормализации, сброса, блокировки, ревизий, Origin и лимита попыток.
DOM-регрессии используют identity-double только в тестовом окружении.
Chromium сам запускает временный сервер и аккаунты, проверяет вход, обязательную
смену пароля, генерацию, административный доступ без смены credentials,
сохранение/перезагрузку, выход и 320/390/768 px. Временная БД удаляется.

[Полная модель и ограничения развёртывания](../docs/strategy-2026-2036/16-authentication-and-access.md).

### Что здесь может пойти не так

- Статический хостинг не исполнит API: нужен Node-сервис за HTTPS-прокси.
- Временный диск потеряет аккаунты: DATA_DIR должен быть постоянным и резервироваться.
- Рабочие учебные профили примут за реальные аккаунты: между ними пока нет автоматической миграции/связи.
- Тестирование назовут полным аудитом: pentest, нагрузка и проверка production-прокси ещё нужны.

### Заполнение и печать проектов документов

В разделе «Документы» для всех 54 форм доступны создание проекта, заполнение реквизитов, редактирование текста, отдельное сохранение редакции, повторное открытие, предпросмотр, скачивание заполненного HTML/Markdown и печать. Предпросмотр и экспорт используют текущие поля, включая ещё не сохранённые изменения. Для PDF выберите «Сохранить как PDF» в системном диалоге печати, если браузер поддерживает эту возможность. HTML можно открыть отдельно и распечатать.

Редактирование проверенного проекта снимает отметку проверки подготовки. Старые записи без содержания открываются в новом редакторе. При возврате к каталогу с несохранёнными изменениями запрашивается подтверждение; при закрытии вкладки используется стандартное предупреждение браузера. Окончательную синхронизацию проверяйте по статусу рабочего пространства: редактор не заменяет серверное сохранение и не работает как автономное хранилище персональных данных.

Это проекты, а не официальная выдача: электронная подпись, юридическое утверждение, регистрация и ФРДО не подключены. Не вводите чувствительные персональные данные. Скачанные файлы остаются на устройстве пользователя и не отзываются платформой. Печатная разбивка страниц зависит от браузера и настроек бумаги; автоматические тесты не подтверждают работу системного диалога печати на каждом устройстве.

### Вход владельца по ФИО на статическом сайте

Для ФИО «Герасимов Дмитрий Сергеевич» предусмотрен отдельный вход без пароля в браузерное рабочее пространство. При вводе полного ФИО поле пароля скрывается. Регистр и повторные пробелы не учитываются. Этот путь не требует `/api/` и работает на GitHub Pages. Сессия хранится в sessionStorage, материалы и настройки — в отдельном localStorage `scm-academy-owner-workspace-v1`. Выход завершает сессию, но не удаляет материалы. Для переноса используется экспорт рабочего пространства.

Это не удостоверение личности и не обход серверной авторизации: серверные пользователи, их пароли и данные недоступны через этот вход. Любой посетитель может открыть такое же отдельное пространство в своём браузере. Изменения здесь не публикуются для всех посетителей сайта; не храните персональные данные других людей. Очистка данных браузера удалит локальное содержимое. Остальные ФИО по-прежнему используют серверный вход с паролем. Если для владельца передан непустой пароль непосредственно в API-клиент, используется обычная серверная авторизация.

### Пользователи и права в браузерном кабинете владельца

Раздел позволяет создавать профили с любой из десяти ролей, изменять ФИО и роль, открывать кабинет профиля, возвращаться к управлению и удалять профиль вместе с его локальным рабочим пространством. Владелец сохраняется отдельно и не удаляется через этот список. Совпадающие нормализованные ФИО не допускаются. Список хранится в `scm-academy-local-accounts-v1`, рабочее пространство каждого профиля — отдельно от пространства владельца. Профили не публикуются и не создают серверных учётных записей: это управление кабинетами на текущем устройстве. Очистка браузерного хранилища удалит их. Вход владельца по ФИО остаётся без пароля.

### Студенческий билет в формате ID-бейджа

Раздел «Студенческий билет» использует горизонтальный макет ID-1 (85,6 × 53,98 мм): фото, ФИО, программа, группа, номер, даты и QR. В кабинете слушателя карточка постоянно размещается справа вверху и открывает полную версию. На узких экранах она остаётся вверху содержимого, не перекрывая интерфейс.

Администратор открывает кабинет нужного слушателя из «Пользователи и права», сохраняет реквизиты и нажимает «Выдать внутреннюю карточку». Номер присваивается, если не введён вручную. Доступен отзыв. Изменение полей выданной карточки переводит её в проект и требует повторной выдачи; просроченная карточка отмечается автоматически. В браузерном режиме всё сохраняется в рабочем пространстве выбранного профиля на текущем устройстве. QR генерируется локально библиотекой qrcode-generator 1.4.4 (MIT), работает без сети и содержит только постоянный идентификатор `SCM-CARD:<id>`, не ФИО. Это не ссылка публичной проверки и не электронная подпись. Внутренняя выдача не заменяет официальное зачисление, государственный студенческий билет или льготы.

Скачивание — автономный HTML с QR и фото; печать/PDF — через браузер, масштаб 100%, без подгонки. Фото: JPEG/PNG/WebP до 300 КБ. Ранее заполненные реквизиты проекта карточки из общего редактора подставляются при первом оформлении нового бейджа. Уже скачанные или распечатанные экземпляры не обновляются и не отзываются удалённо.

### Ручное внесение, поиск и фильтры во всех кабинетах

В девяти кабинетах доступен пункт «Ручные записи»; кабинет аудитора оставлен только для чтения общих предметных записей. Рабочий журнал позволяет создать и отредактировать запись с названием, ФИО/контактом, типом, статусом, датой и содержанием; удалить с подтверждением. Есть комбинированные фильтры по типу, статусу и диапазону дат, поиск по тексту, ФИО и названию, сортировка по дате/названию, счётчик результатов и сброс фильтров. Записи сохраняются в `manualRecords` текущего рабочего пространства и включаются в его обычный экспорт. Браузерные профили сохраняются на устройстве; серверные — через существующее сохранение рабочего пространства. Журнал не подменяет профильную форму зачисления, выдачи документа или выставления оценки и не выполняет эти действия автоматически.

В разделах с карточками и табличными строками добавляется поиск по отображаемому списку, включая текущие значения его полей. Он скрывает несовпадающие элементы без удаления данных; при смене раздела сбрасывается. Поиск не охватывает данные других рабочих пространств, не загруженные записи или публичный сайт. Профильные формы и специализированные поиски разделов сохраняются.

## Правовые справочники и выпускные документы

## Единая оболочка рабочего пространства

Релиз `workspace-20261119-24`: библиотека, формы документов, нормативная база и ОКПДТР открываются внутри основной оболочки (`#resources/...`), с сохранением кабинета и боковой навигации. `unified-pages.js` загружает публичное содержимое в рабочую область, без iframe и повторного входа. Внешние первоисточники и печатные формы остаются отдельными документами по назначению.

Старые публичные URL входят в ту же оболочку через `resource-entry.js`; статический текст сохранён для чтения без JavaScript. Прямой адрес печатной формы не перенаправляется. Фильтры сохраняются в URL, возврат браузером обрабатывается через `popstate`. Техническая версия и обновление перенесены в свёрнутый блок «Сервис и обновления» внизу страницы; инструменты сборки доступны из кабинета.

`npm run test:unified:browser`: вход владельца, единая оболочка без перезагрузки документа и iframe, все 54 формы, нормативная база и классификатор, вложенная статья, старые URL, возврат с фильтрами, сохранённый черновик, ширины 320/390/768/1440.
