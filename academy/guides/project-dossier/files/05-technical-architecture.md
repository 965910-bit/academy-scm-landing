# Технический проект и миграция на сервер

Основатель и разработчик — **Герасимов Дмитрий Сергеевич**. Срез 19.11.2026. Архитектура ниже — целевая, не описание уже развёрнутого сервиса. Сейчас основной сайт публикуется статически; server/server.cjs содержит отдельный серверный код, не работающий на GitHub Pages. Текущая серверная база использует SQLite; PostgreSQL ещё не внедрена.

## Архитектурное решение

Модульный монолит (modular monolith): единое приложение с явными доменными границами вместо ранних микросервисов. Контуры web/API/worker разделяются логически; при росте worker выносится на отдельную машину. Сайт, кабинет и API остаются на одном основном домене. Предлагаемые маршруты: /, /cabinet/, /api/v1/, /files/; старые /academy/ сохраняются совместимыми ссылками/редиректами после проверки маршрутов.

PostgreSQL — авторитетный источник данных. Приватное S3 — содержимое файлов. В БД — владельцы, права, версии, контрольные суммы, сроки хранения, результаты проверки. Клиентский IndexedDB/localStorage — только допустимые черновики/кэш, не общая база и не источник серверных полномочий. Redis и Kubernetes не нужны до измеренной необходимости; задания первоначально могут храниться в PostgreSQL с блокировкой, повторами и идемпотентностью.

## Модули и сущности

| Домен | Основные сущности | Инвариант |
|---|---|---|
| Идентичность | user, organization, membership, session, role | Сервер проверяет организацию и право на каждый запрос |
| Приём | application, admission_decision, enrollment | Решение имеет автора и основание; повтор не создаёт дубль |
| Каталог | education_line, program, course_version | Публикуется конкретная версия с правовым статусом |
| Обучение | group, assignment, submission, attempt, review | Оценка связана с заданием, версией и проверяющим |
| Документы | document, template_version, issue, revocation | Выдача/отзыв журналируются; ФИО не публикуется по угадываемому ID |
| Коммерция | order, payment, refund, receipt | Квитанция провайдера проверяется; callback идемпотентен |
| Интеграции | connection, inbox, outbox, delivery, mapping | Секреты отдельно; повторы не дублируют операцию |
| Управление | audit_event, consent_record, request, retention_rule | История юридически значимой версии не заменяется новым текстом |

Для каждого объекта нужны tenant_id там, где есть организационная принадлежность, стабильный UUID, автор, временные метки UTC и версия для контроля конфликтов. Ролевые права дополняются проверкой связи с объектом: преподаватель видит только назначенные группы; слушатель — свои результаты; комиссия — необходимые поля приёма; администратор поддержки не получает все документы по умолчанию. Кросс-организационные запросы проверяются отрицательными тестами, включая экспорт, поиск, вложения и фоновые задания.

## Инфраструктура и файловая структура

Начальная гипотеза мощности: приложение 8 vCPU/16 ГБ, SSD 100–160 ГБ; Managed PostgreSQL 4 vCPU/8–16 ГБ и 100 ГБ SSD; приватное S3 500 ГБ. Отдельный тестовый контур. Selectel — первый кандидат, Yandex Cloud и Timeweb Cloud — альтернативы для сопоставимой сметы. Ничего не оплачено и не заказано.

Релизы: /opt/scm-platform/releases/<release>, current — ссылка. Конфигурация и секреты: /etc/scm-platform с ограниченными правами. Карантин/обработка: /var/lib/scm-platform/quarantine и processing. Логи не смешиваются с учебными файлами. S3 использует неизменяемые идентификаторы; вложенные человекочитаемые папки документов сохраняются в интерфейсе и метаданных. /files/ выполняет проверку доступа или выдаёт краткоживущую подписанную ссылку. Открытый bucket и постоянные ссылки для приватных документов запрещены проектом.

БД доступна только из приватного контура приложения; администрирование через защищённый канал с персональными учётными записями. Секреты не входят в образ, Git, логи и JS браузера. Доступ к панели провайдера — с многофакторной защитой и резервным восстановлением. Вебинары вынесены из LMS; провайдер выбирается после проверки API, обработки данных и договора.

## API и интеграционные контракты

Все изменяющие запросы аутентифицируются и авторизуются; cookie-сессии требуют CSRF-защиты, безопасных атрибутов и контроля источника. JSON валидируется по схеме; ошибки возвращают код, correlation_id и безопасное сообщение без стека. Ограничиваются размер/тип тела, частота и время обработки. Пагинация и лимиты экспорта предотвращают выгрузку всей БД одним запросом.

Загрузка файла: создание записи → карантин → проверка расширения, сигнатуры, размера и вредоносного содержимого → статус доступности. Конвертация документов и сторонние учебные пакеты исполняются только в изоляции; ZIP-bomb, обход путей и активный HTML проверяются. Конкретный антивирус/песочница ещё не подключены.

Webhook: проверка подписи по исходным байтам, допустимого времени и повторов; запись inbox до ответа; обработка в транзакции; outbox для исходящих событий; ограниченные повторные попытки и очередь ручного разбора. Платёж подтверждается сервером у провайдера. AI-запрос не отправляет паспорт, пароль, чужие ответы или закрытые кейсы по умолчанию. Для всех провайдеров нужны тестовый и производственный режимы, квоты и аварийное отключение.

## План миграции

- Инвентаризировать все browser keys, SQLite-таблицы, файлы и версии; создать безопасные обезличенные фикстуры.
- Ввести PostgreSQL-миграции, ограничения целостности и репозитории данных; не выдавать замену строки подключения за перенос SQLite.
- Перенести права в сервер и убрать доверие к локальному owner-флагу. ФИО остаётся удобным идентификатором, но не доказательством административных полномочий.
- Импорт браузерных данных — явный, с подтверждением владельца, предпросмотром, проверкой происхождения, разрешением дублей и журналом. Не импортировать чужое хранилище автоматически.
- Проверить резервную копию, пробный импорт, количество записей, контрольные суммы и изоляцию организаций.
- Провести переключение в согласованное окно с заморозкой записей, контрольной точкой и планом отката. После новых записей нельзя просто вернуть старую БД и потерять изменения.

### Что здесь может пойти не так
- Сервер доверяет присланным role/tenant_id и раскрывает чужие данные.
- Локальный парольless-вход владельца становится публичной административной дверью.
- Откат приложения выполняют без совместимости схемы БД.
- Фоновый worker или экспорт обходит проверки, работающие в обычном API.
