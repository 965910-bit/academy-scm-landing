Автор: Герасимов Дмитрий Сергеевич. Версия 0.27.0 от 2026-11-19. Все остатки/операции вымышлены. Лицензия распространения собственных материалов подлежит утверждению правообладателем. Экспертизы и апробация не выполнены.

## Запуск и граница среды

Сохраните `database-transactions-lab.py` и `database-acceptance-card.csv`, прочитайте код. Нужен Python 3 со стандартной sqlite3, без внешних пакетов/сети/рабочей БД.

```text
python3 database-transactions-lab.py
```

Основная модель и логическая копия находятся в памяти. Для двух соединений создается отдельная **временная файловая БД**, затем соединения закрываются и временная папка удаляется. Это реальные записи во временное хранилище, не утверждение «вообще без диска». Скачанные исходники не изменяются, произвольный SQL/путь к рабочей БД программа не принимает. При неожиданной ошибке код ненулевой; успешный отчет JSON/код 0. Повторный запуск создает новый учебный набор, не повторяет перемещение в постоянной базе.

## Схема

- `bins(bin_id)` — ячейки, ключ уникален и NOT NULL.
- `products(sku)` — товары, ключ уникален и NOT NULL.
- `stock(bin_id,sku,quantity)` — остаток на зерне ячейка+товар, составной первичный ключ, ссылки на ячейку/товар, CHECK целого неотрицательного количества.
- `movements(movement_id,src,dst,sku,quantity)` — событие; ключ уникален/NOT NULL, положительное целое количество, разные ячейки и составные ссылки на обе строки stock.

FK включаются/проверяются на **каждом** соединении до транзакции. Не полагаться на значение по умолчанию. NULL требует отдельного NOT NULL; внешний ключ сам не доказывает фактическое наличие и не дает полномочий. Параметры SQL связываются через `?`, не конкатенируются из входа. Это не RLS/авторизация.

## Предскажите до запуска

Начало: B1/SKU1=10, B2/SKU1=3, сумма 13, журнал пуст.

M01 переносит 4. В одной транзакции: журнал → условное списание → зачисление → COMMIT. Ожидание:6/7, сумма 13, журнал толькоM01. Проверяется, что списание изменило ровно одну строку при достаточном количестве.

M02 переносит 2, но намеренно падает после списания и до зачисления. Обработчик явно откатывает активную транзакцию. Ожидание:снова 6/7, сумма 13, журнал толькоM01. Не 4/7 и не запись M02. Ошибка одного оператора не является универсальным доказательством отката всей единицы работы.

| Попытка | Ожидается | Подтвержденное состояние после |
| --- | --- | --- |
| M01:перенос 4 | Успех | 6/7, журнал M01 |
| M02:сбой после списания 2 | Ошибка/ROLLBACK | 6/7, журнал M01 |
| M03:списать 7 при остатке 6 | Отказ/ROLLBACK | 6/7, журнал M01 |
| Повтор M01 | Ошибка уникальности/ROLLBACK | 6/7, журнал M01 |
| M04:UNKNOWN-получатель | Ошибка FK/ROLLBACK | 6/7, журнал M01 |

Уникальный ID предотвращает дублирование, но **не реализует успешную идемпотентность API**. Для нее нужен отдельный договор ключа/параметров/возврата прежнего результата. Не выдавать новый ID автоматически и не удалять журнал ради обхода отказа.

## Два писателя и копия

В отдельной временной БД первое соединение выполняет BEGIN IMMEDIATE. Второе с timeout=0 пытается BEGIN IMMEDIATE и получает SQLITE_BUSY. После ROLLBACK первого второе начинает транзакцию и откатывает ее. Это управляемый последовательный сценарий двух соединений, не многопоточный стресс, не доказательство отсутствия всех гонок.

Логическая копия через sqlite3.backup сравнивается по stock/movements. Ожидаются `logical_backup_matches:true`, `foreign_key_check:[]`, `integrity_check:"ok"`, версия схемы 1. Копия в памяти **не доказывает** внешнее резервное хранилище, защиту/ретенцию, восстановление сервиса после сбоя, RPO/RTO или восстановление после отказа диска. Версия схемы — маркер, не проведенная миграция. Рабочие пароли/БД для задания запрещены.

## Дополнительные проверки

Проектные тесты отдельно пытаются вставить неизвестную ссылку, NULL, отрицательный/дробный остаток, дублирующийся ключ; сверяют откат и отсутствие лишнего журнала. Остаток 0 допустим, количество перемещения должно быть положительным целым и не bool; сама схема SQL и Python-API имеют разные уровни проверки типов. Например, Python bool при связывании SQL мог бы стать 1, поэтому запрет есть в API отдельно.

При изменении схемы нужен план миграции/совместимости, копия, безопасная проба и проверка восстановления/отката с реальными свидетельствами. Эта лаборатория создает только новую схему и не реализует промышленную миграцию.
