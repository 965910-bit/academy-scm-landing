Сохранить `testing-router.py`, `testing-cases.csv`, `testing-defect-card.csv` в одну папку, прочитать код. Python 3, только стандартная библиотека;нет сети, пакетов, производственных систем и изменения исходных файлов. Ожидания находятся в открытом CSV;это не защищенный экзамен.

```text

```


Ожидаются 12 проверок,3 провала T03/T11/T12, код завершения 1. Это намеренно дефектная реализация;красный отчет показывает выявление ошибки. Не маскируйте ненулевой код и не удаляйте упавшие случаи. Собственный CSV можно передать через `--cases "папка с пробелом/testing-cases.csv"`;несовпадение схемы, пустой/повторный ID, неразрешенное ожидание или пустой набор дают ошибку валидации, а не успешную приемку.

## Контракт

Вход — Python int, но **не bool**, от 0 до 1 000 000 включительно. Ниже 100000→operator;от 100000→manager. Неверный тип→TypeError, выход диапазона→ValueError. Не приводить строку к числу молча. Результат —маршрут, не одобрение.

| ID | Вход | Ожидание | Buggy |
| --- | --- | --- | --- |
| T01 | 0 | operator | Проходит |
| T02 | 99999 | operator | Проходит |
| T03 | 100000 | manager | Неверно operator |
| T04 | 100001 | manager | Проходит |
| T05 | 1000000 | manager | Проходит |
| T06 | −1 | ValueError | Проходит |
| T07 | 1000001 | ValueError | Проходит |

Два дефекта проявляются в трех случаях:использовано `>` вместо `>=`;`isinstance(value, int)` пропускает bool.9/12=75% —доля прохождения только набора, не доля качества продукта. Reference использует `type(value) is int`, диапазон и включительное сравнение;другие корректные реализации допустимы.

## Минимальный отчет о дефекте T03

- Контракт/версия:0.26.0, включительная граница 100000.
- Среда:записать фактическую версию Python/ОС, не выдумывать чужую проверку.
- Реализация/шаг:`route_buggy(100000)`.
- Ожидание:`manager`;факт:`operator`, воспроизводится на исходном примере.
- Влияние:неверная передача роли на границе;реальный приоритет/серьезность согласуются владельцем по контексту.
- Исправление/проверка:`>=`, повтор T03 и всех 12, отдельно bool. Один исправленный порог не закрывает второй дефект.

Для bool оформить отдельный дефект с T11/T12. Не считать любую ошибку правильным исключением:ожидаются конкретные TypeError/ValueError, не падение из-за окружения/опечатки.

## Регрессия и независимость

Ожидаемое выводится из контракта/таблицы, не вычисляется тем же кодом, который проверяется. Проектные проверки дополнительно подставляют однодефектные мутации:только порог и только bool;набор должен выявлять каждую. Это два примера чувствительности, не полный mutation score/покрытие всех рисков.

Новый порог 120000 —изменение требования:100000 становится operator, добавить 119999/120000/120001 и обновить договор/ожидания новой версией. Не переписывать историю и не «чинить» тест под дефект без согласования.
