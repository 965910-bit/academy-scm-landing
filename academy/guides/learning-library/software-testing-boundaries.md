## 1. Контракт и ожидаемый результат

Тестирование сравнивает наблюдаемое поведение с явным основанием, а не с тем, что «похоже на правильное». В testing-router.py две чистые функции:route_reference и route_buggy. Контракт одинаков:Python int, но не bool, диапазон 0–1 000 000 включительно;ниже 100000 вернуть operator, от 100000 manager;неверный тип TypeError, вне диапазона ValueError. Функция выбирает маршрут, не одобряет заявку.

Тест-кейс фиксирует ID, ссылку на требование/версию, вход, шаг, ожидаемый результат и фактический исход/свидетельство. Для функции шаг —вызов с конкретным значением;ошибка —тоже ожидаемый исход, если это предусмотрено контрактом. Не подменяйте ожидаемое копированием результата текущей реализации.

У Python bool является подклассом int;проверка isinstance(value, int) без исключения bool пропустит True/False. Это важная особенность конкретного языка, а не универсальный типовой закон. В нашем контракте bool запрещен явно;строку"100000" не преобразуем молча в число. Требование GUI-парсинга строки —другая задача и требует другого контракта.

Регрессия —повтор связанных проверок после изменения. ## Словарь

Оракул: Основание ожидаемого результата, независимое от текущего дефектного кода.

Тест-кейс: Вход/условия/шаг/ожидаемый исход с версией и свидетельством запуска.

Граничное значение: Вход на/рядом с границей правила.

Дефект: Несоответствие наблюдаемого поведения согласованному основанию.

Регрессия: Повтор связанных проверок после изменения.

Мутация: Намеренное небольшое изменение кода для проверки чувствительности набора.
