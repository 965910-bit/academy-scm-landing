1. Среда, рабочий каталог и безопасная граница

Linux — семейство операционных систем, а Bash — командная оболочка; одно не является синонимом другого. Этот модуль рассчитан на Bash и доступные grep/cut/sort/uniq/coreutils. Python3 нужен только для подготовки и проверки файлов. Он не устанавливает пакеты, не требует sudo и не меняет системные настройки.

Начните с собственной новой учебной папки, которую создает linux-lab.py --init. До любой записи выполните pwd и ls -la, затем убедитесь, что видите .academy-linux-lab и input/events.log. Точка в имени маркера делает его скрытым для обычного ls, но не защищает его. Никогда не переносите эти команды в каталог реального приложения без анализа.

Абсолютный путь начинается с корня /; относительный вычисляется от текущего каталога. Путь с пробелом заключается в кавычки: cd -- "моя учебная папка". Символ ~ раскрывается оболочкой в определенном контексте, поэтому не считайте "~/lab" универсальной заменой полного пути внутри кавычек. Используйте путь, который вывел инициализатор, и не подставляйте буквальные угловые скобки из пояснений.

2. Файлы, копия и перенаправление

В лаборатории input/events.log — исходник; work/events-copy.log — копия для работы; reports — результаты. mkdir -p -- work reports создает два каталога, cp -- input/events.log work/events-copy.log копирует содержимое. Оригинал не редактируется. mv перемещает или переименовывает, а не создает резервную копию; для сохранения исходника нужен именно осмысленный выбор операции.

Оператор > создает либо обнуляет целевой файл перед записью, >> дописывает в конец. Поэтому grep ... input/events.log > input/events.log опасен: исходник может быть усечен еще до чтения. Всегда разделяйте путь входа и выхода. Перезапуск с >> может удвоить отчет: это не автоматическая история версий.

Кавычки защищают пробелы и специальные символы от нежелательного разбиения и раскрытия. -- завершает разбор опций у поддерживающих его утилит и помогает при именах с дефисом. Эти меры не превращают любую строку в безопасную: не исполняйте скопированные команды без понимания и не используйте eval для обработки имен файлов.

Самостоятельное задание

Создайте рабочую копию и объясните отличие > от >> без изменения исходника.

Разбор задания урока

Допустимы эквивалентные обоснованные решения в пределах условий. Открытая самопроверка, не закрытый экзамен.

3. Поиск строк и точное условие

grep выбирает строки по шаблону. В нашем вымышленном формате уровень стоит в начале и отделен пробелом: grep '^ERROR ' work/events-copy.log. Якорь ^ означает начало строки, пробел после ERROR отделяет уровень от похожего слова. Поиск просто ERROR может поймать это слово в тексте другого уровня.

В выданных 8 строках 3 начинаются с ERROR: missing_price job=J2, duplicate_id job=J3 и missing_price job=J6. Это три сообщения, не три доказанные неисправности и не статус их устранения. Для сохранения: grep '^ERROR ' work/events-copy.log > reports/errors.log. Сохраняйте исходный порядок — он нужен для воспроизводимости.

grep -c считает выбранные строки, а не число вхождений слова внутри строки. wc -l считает символы перевода строки; в нашем файле все 8 записей заканчиваются переводом строки, поэтому получим 8. Для произвольного файла без завершающего перевода строки это не универсальный счет логических записей.

Самостоятельное задание

Получите errors.log и error-total.txt; объясните, что именно равно 3.

Разбор задания урока

grep '^ERROR ' work/events-copy.log > reports/errors.log; grep -c '^ERROR ' work/events-copy.log > reports/error-total.txt.3 — число строк уровня ERROR в заданном файле, не число устраненных проблем.

Допустимы эквивалентные обоснованные решения в пределах условий. Открытая самопроверка, не закрытый экзамен.

4. Стандартные потоки и коды завершения

Стандартный вывод stdout обычно содержит результат, стандартный поток ошибок stderr — диагностическое сообщение. > перенаправляет stdout, 2> — stderr. Пустой файл результата сам по себе не различает отсутствие совпадений и ошибку чтения. Для решения смотрите диагностический поток и код завершения.

По прочитанной документации GNU grep обычный код 0 означает выбранные строки,1 — отсутствие выбранных строк,2 — ошибку. Для других реализаций возможны отличия, а режим -q имеет особенность при сочетании совпадения и ошибки; в этом упражнении он не применяется. Проверяйте локальную документацию при переносе.

После grep '^FATAL ' work/events-copy.log код равен 1, потому что таких строк нет. Сохраните $? немедленно: следующая команда изменит его. В оболочке с set -e намеренно ожидаемый ненулевой код обрабатывайте в условии if, а не рассчитывайте, что выполнение автоматически продолжится. Эталонный сценарий делает это явно.

Самостоятельное задание

Сохраните код поиска FATAL в fatal-status.txt, не приняв отсутствие совпадений за отсутствие файла.

Разбор задания урока

В if выполнить grep '^FATAL ' work/events-copy.log > reports/fatal.log; в ветке else первой командой status=$?, затем printf '%s\n' "$status" > reports/fatal-status.txt. Ожидается 1 и пустой fatal.log; ошибка чтения — другой результат, его не подменять 1.

Допустимы эквивалентные обоснованные решения в пределах условий. Открытая самопроверка, не закрытый экзамен.

5. Конвейер и статус всей цепочки

Конвейер | соединяет стандартный вывод одной команды со стандартным вводом следующей. Для подготовленного errors.log команда cut -d ' ' -f2 выделяет второе поле: missing_price, duplicate_id, missing_price. Это допустимо только для нашего простого формата с одиночным пробелом; это не надежный универсальный парсер произвольных логов.

В Bash по умолчанию статус конвейера определяется последней командой. Поэтому ошибка первой команды может быть замаскирована успешным wc или другим потребителем. set -o pipefail делает ненулевым результат цепочки при ошибке ее звена: берется статус самого правого завершившегося ненулем звена. Это свойство Bash, не утверждение обо всех оболочках.

В нашем эталоне set -eu и set -o pipefail используются вместе с явной обработкой ожидаемого grep=1. Настройки сами по себе не доказывают правильность отчета: команда может успешно обработать не тот файл. Проверяйте и коды, и содержимое, и выбранные пути.

Самостоятельное задание

Покажите, почему status0 от последнего wc не доказывает успешность чтения входа.

Разбор задания урока

В отдельной учебной Bash-команде grep по несуществующему файлу может вернуть 2, а wc вернуть 0; без pipefail общий код 0. С pipefail общий ненулевой. Ненулевой ожидаемый поиск без совпадений нужно интерпретировать отдельно, а не скрывать через || true.

Допустимы эквивалентные обоснованные решения в пределах условий. Открытая самопроверка, не закрытый экзамен.

6. Группировка, sort и uniq

По прочитанной документации uniq объединяет только соседние одинаковые строки. Наши missing_price разделены duplicate_id; uniq -c без подготовки не даст одной общей строки missing_price=2. Сначала сортируют ключи либо применяют иной обоснованный способ группировки.

Репродуцируемая команда: cut -d ' ' -f2 reports/errors.log | LC_ALL=C sort | uniq -c > reports/error-counts.txt. Результат:1 duplicate_id и 2 missing_price, порядок после сортировки C. Отступы перед счетом могут отличаться по выводу утилиты; проверяющий допускает пробельные отступы, но не дубли ключей и неверные числа.

Сумма счетчиков 1+2=3 должна совпасть с error-total.txt и числом сохраненных строк errors.log. LC_ALL=C фиксирует порядок сравнения для этого ASCII-набора, а не является универсальным выбором для русскоязычной сортировки. Категория missing_price=2 не означает две разные причины или два устраненных инцидента.

Самостоятельное задание

Получите агрегат и контрольную сумму; объясните необходимость sort перед uniq.

Разбор задания урока

Ключи идут missing_price/duplicate_id/missing_price; после sort одинаковые соседствуют, uniq -c дает 1 и 2. Сумма 3 совпадает с тремя ERROR-строками. Допустима другая группировка с тем же содержимым и объяснением.

7. Права на учебный отчет и границы проверки

На Linux у файла есть владелец, группа и биты прав чтения r, записи w, выполнения x. Для reports/note.txt команда chmod 600 оставляет чтение/запись владельцу и снимает эти права у группы и остальных в обычной модели POSIX. Это не шифрование и не защита от привилегированного администратора, резервных копий, ACL или иных механизмов среды.

Создайте note.txt с объяснением 8/3, группировки 1/2 и смысла grep=1, затем chmod 600 -- reports/note.txt. Не применяйте chmod -R к домашней папке,777 к системным каталогам или sudo: они не нужны. Изменение прав на одном учебном файле не дает права управлять доступом реальных пользователей.

Проверяющий смотрит режим 600 на POSIX и непустую заметку; смысл текста оценивает преподаватель. На другой файловой системе модель прав может отличаться: не объявляйте такую среду эквивалентной Linux только потому, что Python запустился. Лаборатория не обучает настройке серверов, служб или сетевой безопасности.

Самостоятельное задание

Разбор задания урока

  • Подменить ошибку чтения кодом отсутствия совпадений или успехом последнего звена
  • Выдать PASS за квалификацию; применять sudo или рекурсивную смену прав к системным каталогам

Q8. Что меняет pipefail?

Ответ, основание и объяснение

Дает статус самого правого ненулевого звена, либо 0 если все успешны.

Успех потребителя не маскирует ненулевой статус производителя.
