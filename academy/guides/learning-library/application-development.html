1. Контракт и разделение ответственности

CLI (Command Line Interface — интерфейс командной строки) получает путь к входу, вызывает расчет и выводит результат. В application-lab.py разделены load_request, calculate и main: чтение/разбор формата, правила предметной области и интерфейс/коды завершения. Это позволяет проверять арифметику без запуска терминала и отдельно проверять поведение при плохом файле. Наличие трех функций само по себе не доказывает хорошую архитектуру любой системы.

Контракт JSON (JavaScript Object Notation — текстовый формат обмена данными): объект только с currency и lines, валюта ровно RUB; от 1 до 100 позиций. Каждая содержит только line_id, qty, unit_price_kopecks. ID вида L00–L99 уникальны. qty — Python int, но не bool, от 1 до 1000; цена — целые копейки от 0 до 100000000. Пустой набор, неизвестные/отсутствующие поля и повторы ID отвергаются, не исправляются догадкой.

Сумма позиции равна qty×unit_price_kopecks; сумма набора — сумма позиций. В application-request.json L01: 2×12550=25100, L02: 3×9990=29970, L03: 1×0=0 копеек. Итого 55070 копеек, то есть 550,70 рубля. Нулевая цена разрешена контрактом расчета, не является разрешением на реальную бесплатную поставку. Здесь нет скидок, НДС, округления налогов, наличия товара, заказа или оплаты.

2. Валидация до результата и ошибки

Синтаксически правильный JSON не гарантирует допустимые предметные данные: true, дробь, отрицательное количество, повторный ID или поле password могут быть допустимы для формата, но не для этого контракта. load_request ограничивает фактическое чтение 65537 байтами и отклоняет размер свыше 65536, повторные ключи JSON и NaN/Infinity. calculate затем проверяет структуру/типы/диапазоны. Это узкие меры, не полный безопасный парсер/песочница для враждебного ввода.

Валидация всех позиций заканчивается до возврата/печати результата. Если вторая позиция содержит qty=true, расчет не выдает частичный итог первой. Ошибка идет в stderr, код 2, stdout пуст. Корректный вызов дает один JSON в stdout и код 0. Ненулевой код нужно сохранить в протоколе; нельзя скрыть ошибку, подставить ноль или печатать отладочную строку в поток машинного результата.

Отсутствующий файл, неверная кодировка, поврежденный JSON и чрезмерная вложенность также обрабатываются как отказ входа в рамках пойманных исключений. Не использовать eval, выполнение команд из файла или автоматический сетевой поиск «исправления». Указанный пользователем путь читается локально: это не серверный API, не разграничение доступа к произвольным файлам и не разрешение обрабатывать секреты.

3. Проверки, крайние случаи и изменение

Позитивный тест сверяет 55070 с независимой ручной арифметикой, а не вызывает calculate еще раз для получения ожидаемого. Негативные тесты: повтор L01, пустой набор, qty0/1001/true, цена−1/дробь, неверная валюта/лишнее поле, повтор ключа и NaN. Границы qty1/1000 и цены 0/100000000 допустимы; размер/типы/целочисленность проверяются отдельно.

Граничный набор 100 уникальных ID и qty1000/цена 100000000 дает 100×1000×100000000=10000000000000 копеек. Этот числовой тест не является нагрузочным испытанием. 101 позиция запрещена. Исходные объекты не мутируют: calculate строит новый результат. Проверка побочного эффекта важна, иначе повторный запуск мог бы зависеть от уже измененных данных.

Запрос добавить скидку/другую валюту меняет контракт: нужны единицы, формула, порядок/округление, диапазоны, версия и новые ожидаемые результаты. Нельзя просто добавить поле в JSON и молча игнорировать его ради зеленого запуска. Регрессия повторяет прежние допустимые случаи в области совместимости; миграция/отказ старого формата фиксируются отдельно.

Нет: сначала определить смысл/единицы/порядок/округление/диапазон и версию, затем код/ожидания/регрессию. Текущий контракт отклоняет лишнее поле, не применяет скидку и не должен его молча игнорировать.

Новая потребность меняет контракт, не только файл данных.

Основание: собственный учебный кейс и урок 3, версия 0.31.0.

Допустимые варианты: Сохранить старую версию и разработать новый явный формат/миграцию.

  • 2 балл(а): Спецификация/версия/новые тесты и отказ неизвестного поля
  • 1 балл(а): Верно нужна версия, но неполны формулы/приемка
  • 0 балл(а): Молча игнорирует/принимает скидку без определения
