# Предметная проверка и апробация учебного комплекта

Автор методического чек-листа: Герасимов Дмитрий Сергеевич. Версия 0.5.0 от 19.11.2026.

Это инструкция для будущего проверяющего, не свидетельство проведенной экспертизы. Нельзя отмечать «пройдено» на основании только автоматической проверки структуры.

## 1. Зафиксировать предмет проверки

- ID и версия материала, дата, аудитория, входные знания, заявленные действия слушателя.
- ФИО и подтвержденная предметная компетенция фактического проверяющего; не назначать автора автоматически экспертом по всем направлениям.
- Область проверки и конфликт интересов. Редактура текста не заменяет предметную экспертизу.
- Перечень файлов: уроки, задачи, ответы, рубрики, шаблоны и лаборатории одной версии.

## 2. Содержание и полнота

Для каждого результата обучения пройти цепочку: объяснение → разобранный пример → самостоятельная практика → задание проверки → эталон или рубрика.

Проверить определения, единицы, допущения, исключения, отсутствие противоречий и опасных рекомендаций. Отдельно перечислить, что еще требуется для полной программы по роли. Четыре вводных урока не объявлять исчерпывающим курсом по профессии.

Фиксация замечания: ID материала/урока, точная проблема, риск, предложенное исправление, основание, ответственный, срок, повторная проверка.

## 3. Ответы и задания

- Решить каждую задачу независимо до просмотра эталона.
- Проверить вычисления, знаменатели, округление, NULL/пропуски, граничные случаи и неоднозначность.
- Указать допустимые альтернативные решения и какие ошибки допускают частичный балл.
- Проверить связь критической ошибки с риском; не назначать ее произвольно ради строгости.
- Проверить согласованность двух оценщиков на одинаковых обезличенных примерах.
- Открытые ответы использовать только для самопроверки; закрытая аттестация требует другого банка и серверных прав. Ни Markdown, ни свернутый HTML секретности не дают.

## 4. Источники и применимость

- Реальный автор, название, URL, дата/редакция, дата доступа, объем прочитанного, ограничения использования.
- Проверить статус: архив, отмена, новый выпуск, закрытый раздел или устаревший интерфейс.
- Обзорная карточка не означает чтения учебника. Зарубежное руководство не является российской правовой нормой.
- Открытый доступ не означает права копирования в коммерческий курс; права проверяются отдельно.
- По регулируемому обучению — отдельное заключение о требованиях программы, преподавателей, допуска, практики и документов. Отсутствие найденного запрета не равно разрешению.

## 5. Апробация

После необходимых предварительных проверок провести безопасный пилот на согласованной аудитории. Для опасных/регулируемых действий не использовать неподтвержденный кабинетный материал как разрешение на рабочую практику.

Зафиксировать входной уровень, формат, версию, число участников, помощь, время, ошибки материала и критерии. Не публиковать персональные результаты в открытом журнале. Сохранить в разрешенном хранилище протокол; в публичной версии — только обезличенная допустимая ссылка/описание доказательства.

Отдельно измерять просмотр, самостоятельное выполнение, повторное выполнение и удовлетворенность. Не объявлять причинную эффективность по одной малой группе.

## 6. Решение и обновление

Раздельные этапы: subject_review, legal_review, answer_review, pilot. Возможные записи: pending, changes_requested, passed. Для passed необходимы фактический проверяющий, дата и описание/ссылка на доказательство. Такая запись не дает автоматически статуса утвержденной образовательной программы.

В changes записать прежнюю/новую версию, причину, затронутые уроки/ответы, исполнителя и дату. Повторить проверки после изменения чисел, правил, источника, ПО или условий практики. Не стирать историю и не переносить положительное заключение на существенно измененный комплект автоматически.

Закрытие редакционных этапов не равно лицензированию, квалификации слушателя или допуску к работе. Эти решения проверяются отдельно.
