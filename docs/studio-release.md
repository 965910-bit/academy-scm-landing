## Реестр требований

`academy/guides/completion-ledger/requirements.json` содержит 108 требований из доступного диалога. Генератор: `python scripts/build-completion-ledger.py`. Публичная версия: `/academy/guides/completion-ledger/`. Это не заявление о 100% готовности; статусы различают локальный механизм, серверный код, адаптер без провайдера, частичную реализацию, внешнюю зависимость и аудит. Прежние отчёты остаются историческими снимками; новый реестр имеет приоритет при оценке поставки 31.

## Новая студия внутри существующей LMS

Точка входа: `/academy/?lms=studio-content#cabinet`. Новые разделы находятся в том же переключателе процессов, что приём, договоры, оплата и расписание. Каталог программ и участники общие: `state.lmsOperations`. Новые коллекции — вложенный `studio`, старые данные не удаляются и не требуют миграции.

1. **Контент:** текстовые и медиа-блоки, drag-and-drop и кнопки перемещения, публикация, версии. Визуальный редактор с базовым форматированием, сохранение HTML через DOMPurify. При показе HTML снова очищается. Изображения увеличиваются в диалоге. Видео/аудио используют встроенные браузерные плееры; контрольная точка останавливает видео и записывает ответ без автоматического оценивания. Вложения — HTTPS-ссылки, не приватное файловое хранилище.
2. **Вопросы:** один ответ, несколько ответов, последовательность, открытый ответ. Тема, сложность, вес, комментарий/рубрика и ссылка на медиа. Для множественного выбора используется полное совпадение множества, не частичный балл.
3. **Тесты:** воспроизводимая случайная выборка, перестановка вариантов с сохранением индексов, ограничение попыток, дедлайн, черновик ответов, скрытие и отложенное раскрытие результата. Время проверяется локальными часами, это не защита от владельца браузера. Просроченная попытка не получает баллы. При открытых вопросах нужен балл человека по рубрике. Итог подтверждается преподавателем.
4. **Сертификаты:** после подтверждения успешной попытки может автоматически появиться внутренняя запись, срок переаттестации, скачиваемый печатный HTML и отзыв с причиной. Это не документ об образовании, ЭП или публичный реестр; ранее скачанную копию нельзя технически отозвать у получателя.
5. **Совместная работа:** форумы, новости, блоги, лента чата, ответы по ID, ссылки-вложения, модерирование, лайки, подписки и опросы. Это локальная совместная модель, не сетевой real-time чат. Участники видят опубликованные сообщения своей организации; в браузерном JSON это не граница безопасности. Wiki хранит историю и проверяет ревизию. Глоссарий поддерживает синонимы и несколько определений.
6. **360° / KPI:** критерии, роли оценщиков, один ответ от профиля, агрегирование. При анонимном режиме агрегат скрыт до трёх ответов, но локальный JSON содержит идентификаторы и не гарантирует анонимности. KPI хранит базу/цель/факт/единицу/период/источник. Причинный эффект обучения не заявляется.
7. **Вовлечение:** баллы один раз за подтверждённый тест, уровень, внутренний бейдж, рейтинг, магазин, остатки, атомарное списание, подтверждение выдачи. Это не денежный инструмент и не игровой движок Jeopardy/Wheel of Fortune.
8. **Отчёты:** фильтры организации, подразделения, должности, периода; реальные XLSX и печать/PDF через браузер. Сигналы риска объясняются просрочкой/доработкой, а не обученной моделью. ROI — сценарий с долей атрибуции, не доказательство эффективности.
9. **Локальный помощник методиста:** план и открытый вопрос по исходному фрагменту, только черновик. Не называется LLM-генерацией. Прежний внешний ассистент и калькулятор затрат сохранены.

### Что здесь может пойти не так

- Локальный профиль и скрытый результат принимаются за защищённую серверную учётную запись и тайну ответов.
- Автоматический сертификат после проверки ошибочно принимается за законный диплом или аккредитацию.
- Выборка, баллы и 360° используются без валидированных критериев и согласованного процесса.
- Несколько независимых рабочих пространств редактируются без обмена; общего синхронного сервера в этой поставке нет.

## XLSX и учебные пакеты

Импорт участников читает первый лист настоящего XLSX через `read-excel-file`, CSV/TSV сохранены. Размер файла до 2 МБ, до 1000 строк, проверка распакованного объёма и числа ZIP-записей; макросы и формулы не исполняются. XLSX-экспорт использует `write-excel-file`, а не переименование CSV.

ZIP пакуется через `fflate`. Экспорт SCORM 1.2 / 2004 включает manifest, один SCO и базовый runtime инициализации/завершения/commit. Полный SCORM 2004 sequencing, сертификация совместимости и произвольный сторонний SCO runtime **не реализованы**. Удалённые медиа в экспорте требуют сети. Инспекция ZIP ограничивает размеры, пути и XML entities; чужой JavaScript не исполняется. Пакеты Академии можно импортировать новым курсом с черновиками блоков. H5P пока только распознаётся по структуре, не проигрывается.

Сборка локального bundle: `npm ci --prefix academy && npm run build:studio --prefix academy`. Исходник: `scripts/studio-packages-entry.js`. Bundle закоммичен для статического сайта, CDN не требуется. Лицензии зависимостей: `academy/vendor/licenses/`. Версии зафиксированы lock-файлом.

### Что здесь может пойти не так

- Наличие `imsmanifest.xml` принимается за полную совместимость со всеми LMS.
- H5P-инспекция принимается за H5P-плеер.
- Разрешение открывать внешнюю ссылку раскрывает провайдеру сведения о посещении; персональные данные нельзя включать в публичные URL.

## Серверная безопасность и роли

Модуль `server/tenant-security.cjs` подключён к существующему серверу. API требует настоящей серверной сессии. Локальный беспарольный вход владельца не получает серверный cookie.

### Политики объектов

- GET `/api/tenant/membership`: организация, подразделение, менеджер и права текущего пользователя.
- POST `/api/tenant/policy`: администратор задаёт `read`/`write` типы и scope `self`, `department`, `tenant`.
- POST `/api/tenant/member`: назначение организации/подразделения/менеджера/политики. Межорганизационное перемещение и выдача административной политики другому пользователю требуют суперадминистратора.
- GET/POST `/api/tenant/objects`: tenant выводится из серверной сессии; подстановка tenant клиентом игнорируется. Чтение ограничено типами и областью, изменение проверяет те же права и ревизию. Не даём раскрыть чужой ID через запись. Все изменения журналируются.

**Граница:** это настоящий server-side row filtering нового API, а не полная миграция всех старых API. Старые workspaces/workflows и локальные коллекции не объявляются защищёнными этой новой политикой.

### TOTP

GET `/api/security/totp`, POST `/api/security/totp/setup`, POST `/api/security/totp/confirm`.

Настройка выдаёт секрет и otpauth URI только в текущей сессии. До подтверждения кодом второй фактор не активируется. После подтверждения выдаются восемь одноразовых резервных кодов; в БД хранятся их SHA-256 hashes. При входе используется поле `otp`, принимается TOTP или резервный код. Повторное использование кода отвергается; ограничения попыток входа распространяются и на второй фактор. Секрет шифруется AES-256-GCM ключом `totp-encryption.key` в DATA_DIR с правами 0600. Ключ необходимо резервировать отдельно от публичного репозитория: потеря ключа лишает возможности расшифровать секреты. Нельзя складывать secret/recovery codes в учебные материалы.

Данные владельца и его вход по ФИО не изменялись. Включение TOTP — осознанное действие пользователя серверной учётной записи, не навязываемая смена реквизитов.

### Что здесь может пойти не так

- Новый API объявляется защитой всей платформы без миграции прежних хранилищ.
- Теряются резервные коды и ключ шифрования; нужна отдельная операционная процедура восстановления.
- Веб-интерфейс запускается на Pages без `/api/`, но пользователь ожидает серверную функцию. В этом случае UI выводит явную ошибку, не сохраняет фиктивный успех.

## OIDC SSO

`server/oidc.cjs` реализует authorization code flow + PKCE S256, одноразовое состояние с cookie, nonce, проверку подписи JWT, issuer, audience, срока и iat через `jose`. Google и Microsoft работают как настраиваемые OIDC IdP; реальных клиентов этой поставкой не регистрировали.

Серверная переменная `SCM_OIDC_PROVIDERS` — JSON-объект конфигураций. Пример формы **без секретов**:

```json
{"google":{"title":"Google","issuer":"https://accounts.google.com","clientId":"<выданный IdP client id>","clientSecret":"<серверный секрет>","redirectUri":"https://ваш-домен/api/oidc/callback"}}
```

Для Microsoft используется точный tenant-specific issuer из вашей регистрации. Не подставляйте неподтверждённый multi-tenant issuer. Все endpoints требуют HTTPS. Callback URI регистрируется у IdP буквально.

- GET `/api/oidc/providers`: только названия провайдеров, без client secret.
- GET `/api/oidc/start?provider=google`: начало входа.
- GET `/api/oidc/callback`: обмен кода и создание сессии.
- POST `/api/oidc/link`: администратор связывает **точный subject** с существующим активным пользователем. Совпадение e-mail не используется как разрешение войти в чужой аккаунт.

Если локальный TOTP уже включён, SSO не обходит его: пользователь направляется на парольный вход с фактором. Полный комбинированный SSO+локальный MFA flow пока не реализован. SAML и LDAP не называются реализованными на основании наличия OIDC.

Runtime-зависимость `jose` зафиксирована в корневом package-lock.json; для серверного запуска нужен `npm ci`. Существующий пример render.yaml обновлён только в части buildCommand. Платный сервис не создавался и не оплачивался.

### Что здесь может пойти не так

- Неверно задан issuer или callback URL; вход должен быть отклонён, а не пропущен.
- Администратор связывает не тот subject; ручная привязка требует проверки личности.
- Ключи провайдера или сеть недоступны; локальный парольный вход остаётся отдельным путём.

## Реальные адаптеры, пока без подключённых провайдеров

`server/integration-services.cjs` и `/api/integrations/capabilities`, `/api/integrations/send`:

- **xAPI:** `SCM_LRS_URL`, `SCM_LRS_AUTH` (готовый Authorization header, только сервер). Передача до 100 statements, actor задаётся серверной сессией, проверяется квитанция LRS. Результаты, введённые сотрудником, не объявляются автоматически удостоверенными.
- **CRM/ERP webhook:** `SCM_WEBHOOK_URL`, `SCM_WEBHOOK_SECRET`. HMAC-SHA256 по точным байтам, event ID, тайм-аут, запрет redirects. HTTP 2xx — приём HTTP, не подтверждение применения в ERP. Это не 20 готовых типовых коннекторов и не гарантированная доставка с retry queue.
- **BigBlueButton create:** `SCM_BBB_URL`, `SCM_BBB_SECRET`. Подписанный запрос создания встречи и проверка SUCCESS. Join/записи/автоматическая посещаемость ещё не подключены.

Вызовы выполняются только сотрудником при явном согласии. Нет конфигурации — нет сетевого вызова. Внешние API credentials не сохраняются в браузере. Провайдеры не подключались и расходы не создавались.

### Что здесь может пойти не так

- Неподключённый адаптер объявляется работающим сервисом основного домена.
- Успешная квитанция передачи принимается за законность обработки или достоверность результата.
- Внешние тарифы, поддержка, отладка и человеческая проверка не включаются в бюджет. Новых LLM-вызовов в этой поставке нет; стоимость внешней модели остаётся в прежнем калькуляторе и конфигурации.

## Проверка и публикация

Доменные тесты охватывают типы вопросов, таймеры, попытки, черновики, проверку человеком, версии, 360°, KPI, награды и запреты. Серверные тесты: RFC-вектор TOTP, шифрование/одноразовость, HTTP login с фактором, tenant/manager/owner filtering, конфликты, криптография JWT и OIDC flow с PKCE/state; внешние адаптеры проверяются контролируемыми fake transport responses, не реальными платными сервисами.

`npm test --prefix academy` — общий набор. `npm run test:studio:browser --prefix academy` — реальный браузерный сквозной сценарий: блоки/SCORM ZIP, очистка HTML, тест/черновик/проверка/сертификат, форум/wiki/глоссарий, 360/KPI, награды, XLSX экспорт и повторный импорт, 320/390/768/1440 и автономная перезагрузка. Для браузера задаётся CHROMIUM_PATH, на Linux может требоваться LD_LIBRARY_PATH.

Полная производственная готовность не заявляется: серверные функции на статическом Pages не запускаются. Для завершения всех 108 требований остаются перечисленные в реестре внедрения, подключения и аудиты.
