## 1. Условия и результат

Нужно объяснить решения по 12 вымышленным адресам, исправить два опасных совета и передать факты учебного события без секретов и необоснованных выводов. Нельзя переходить по адресам, загружать реальные письма/вложения, вводить пароли/коды, менять учетные записи или отправлять рабочие данные в публичный сканер/ИИ. Все примеры содержат вымышленные имена под `.invalid`; DNS, сайт, сертификат и существование организации не проверяются. Текст URL — данные, не команда к переходу.

Материалы: `safe-work-links-case.csv`, `safe-work-links.py`, этот текст. Бумага и таблица допустимы вместо запуска с честной записью «код не запускался». Сначала независимый разбор, потом открытый эталон. Открытые ответы не доказывают самостоятельность.

## 2. Политика учебной проверки

Порядок важен: отчет возвращает первый не пройденный шаг, не перечень всех возможных проблем.

1. Вход — текст длиной 1–2048 символов. Неверный тип/размер блокирует весь расчет как ошибку данных.
2. Только ASCII с кодами 33–126, без обратной косой черты. Пробелы, перевод строки, табуляция и Unicode дают `noncanonical_input` до парсера: не исправлять строку молча.
3. `urlsplit` разбирает строку. Схема должна быть `https`, иначе `non_https`. Относительные адреса не разрешены.
4. Любая пользовательская часть перед @ дает `userinfo`. Узел из такой строки не выводится в отчет. Ошибка парсинга/порта, отсутствие authority/узла дают `invalid_authority`.
5. Процент в authority, конечная точка узла, пустой явный порт (двоеточие в конце authority), метка `xn--` и форма узла вне ограниченного ASCII-шаблона дают `noncanonical_authority`. Это исключение из учебной политики, не доказательство вредоносности Unicode/punycode или всех таких адресов.
6. Требуется точный узел `portal.example.invalid`. Иной узел — `host_not_listed`; поддомены/суффиксы не разрешены автоматически. Регистр узла не различается парсером.
7. Порт отсутствует или численно равен 443, иначе `port_not_listed`. Невалидный порт был отвергнут на шаге 4. Эта политика допускает числовую запись `0443`, потому что сравнивает число; это не проверка байтового совпадения authority.
8. Любой знак `?` или `#`, даже с пустым значением, дает `extra_components`. Скрипт не разбирает вложенные URL, не следует редиректам.
9. Путь пустой (трактуется как `/`), `/`, `/help` или `/training`; иной путь дает `path_not_listed`. Регистр пути, проценты, `..` и повторные `/` не нормализуются/не декодируются.
10. После всех шагов только `manual_verification_required`. Значения `safe`, `trusted` или «разрешено входить» отсутствуют.

Это намеренно узкий учебный контракт. Он не является полным валидатором URL/браузерного стандарта, антивирусом, анализатором фишинга, серверным сетевым фильтром или защитой от SSRF (Server-Side Request Forgery — принуждение сервера к нежелательным сетевым запросам). Сетевых запросов здесь вообще нет. Даже совпавший узел может быть скомпрометирован, а HTTPS сам по себе не доказывает добросовестность.

## 3. Команда и ограничения файлов

Скачайте CSV и Python в отдельную новую папку, прочитайте исходники. Нужен Python 3 со стандартной библиотекой:

```sh
python3 safe-work-links.py --directory .
```

Код 0 — завершен расчет по учебной политике, не одобрение адресов. Код 2 — ошибка входа/чтения с пустым stdout и диагностикой stderr. JSON печатается в stdout; файлы не записываются, сеть/браузер/почта не вызываются. Не перенаправлять stdout в исходный CSV. Пути/родительские ссылки/гонки файловой системы не изолированы: доверенные локальные файлы, не публичный сервис загрузки.

CSV: UTF-8 с необязательным BOM, запятая, точный порядок `case_id,url`, 1–100 строк, до 65536 байт. Уникальные ID `L00`–`L99`. Неверная схема, дубли ID, лишние поля, пустой URL/URL длиннее 2048 блокируют весь расчет; отдельные неподдерживаемые формы URL дают коды политики. Некорректная форма — не то же, что поврежденная структура CSV. Отчет не повторяет исходный URL или userinfo; известные узлы могут выводиться только как текст. Не адаптировать пример для реальных секретов.

## 4. Независимый эталон L01–L12

| ID | Первый код | Основание и ограничение |
|---|---|---|
| L01 | manual_verification_required | Точный узел/схема/путь; все равно нет доказательства безопасности |
| L02 | non_https | Схема http не входит в политику |
| L03 | host_not_listed | Полное имя заканчивается other.invalid, подстрока портала не совпадение узла |
| L04 | userinfo | Часть до @ не целевой узел; отказ без вывода пользовательской части |
| L05 | manual_verification_required | Регистр узла неважен, явный порт 443 и /help разрешены лишь синтаксически |
| L06 | port_not_listed | 8443 не входит в политику |
| L07 | noncanonical_authority | Конечная точка узла не поддерживается |
| L08 | extra_components | Есть запрос next; его содержимое не выполняется и редирект не доказан |
| L09 | path_not_listed | `%74raining` не декодируется в training |
| L10 | non_https | Относительный адрес не получает схему автоматически |
| L11 | noncanonical_authority | Punycode не поддерживается данным учебным контрактом |
| L12 | invalid_authority | Нечисловой порт вызывает ошибку разбора |

Итого 2 случая соответствуют узким условиям, но все 12 требуют осторожного решения/независимой проверки, ни один не отмечен безопасным. Доля 2/12 не оценка количества фишинга, качества организации или эффективности защиты. Все случаи вымышлены.

4. 20 минут: исправить два ошибочных совета и обосновать, почему нельзя выдавать технический признак за разрешение.
5. 20 минут: разобрать сценарии учетной записи/вложения и написать сообщение о событии без самовольных действий.
6. 20 минут: собрать протокол передачи, реестр непроверенного и сверить рубрику. Подлинное наблюдение преподавателя не подменять самостоятельным письменным разбором.

### Изменения по одному на исходной копии

- L06: порт 8443 заменить на 443 → `manual_verification_required`, но не «безопасно».
- L08: убрать весь запрос вместе со знаком `?` → `manual_verification_required`; оставить только `?` → по-прежнему `extra_components`.
- L09: заменить путь на буквальный `/training` → `manual_verification_required`. Это учебное изменение входа, не разрешение перехода.
- L01: добавить ведущий пробел или табуляцию → `noncanonical_input` до парсера. Не подчищать автоматически.
- L01: `/training` заменить на `/TRAINING` → `path_not_listed`; добавить фрагмент `#ok` → `extra_components`.
- Дублировать ID L01 или оставить пустой URL → полный отказ, код 2, stdout пуст. Нельзя удалять неудобный случай ради зеленого отчета.

## 6. Ошибочные советы и модельные исправления

**Совет А:** «Адрес начинается с https и имени портала, поэтому сразу вводим пароль». Исправление: HTTPS и видимое начало не подтверждают назначение/право входа. В L04 имя до @ — пользовательская часть; L03 — иной полный узел. Даже L01 требует независимого подтверждения запроса, источника и прав. Учебные адреса не открываем, реальные пароли не вводим.

**Совет Б:** «Скрипт вернул код 0 — инцидента нет, письмо удалим». Исправление: код 0 — расчет строк по синтаксическому контракту; сообщения/устройства/учетные записи вообще не исследованы. Наличие/отсутствие инцидента не установлено. Подозрительное действие остановить, передать минимальные факты по известному каналу и следовать утвержденному порядку сохранения/удаления свидетельств. Не уничтожать единственную копию самовольно.

Допустимы эквивалентные обоснованные формулировки, таблица «признак/что доказывает/что не доказывает/следующий шаг». Неприемлемы реальные проверки на чужих системах или выдуманный факт расследования.

## 7. Учетная запись, вложение и сообщение

Ситуация В: неожиданный MFA-запрос повторяется. Модель: не подтверждать, не передавать код, проверить события по известному разрешенному пути и сообщить ответственной роли. Восстановление, смена секрета и отзыв сессий — по полномочиям и процедуре; лаборатория учетные записи не меняет. Пароли/резервные коды здесь не нужны.

Ситуация Г: неизвестный отправитель просит открыть архив и включить активное содержимое. Модель: не открывать/не включать, независимо подтвердить запрос/источник, передать минимальные метаданные уполномоченной роли. Не отправлять рабочий архив в публичный сканер/ИИ без основания. Хеш/расширение не доказывают отсутствие вредного кода.

Ситуация Д (только вымышленная): человек уже перешел по ссылке, но не вводил сведения и не запускал файлы. Образец сообщения: «Учебное событие, не реальный инцидент. В 14:10 UTC по условию выполнен переход из сообщения. Ввод данных/подтверждение входа/загрузка/запуск не наблюдались. Дальнейшее действие остановлено. Прошу уполномоченную роль определить проверку и порядок сохранения свидетельств. Компрометация и отсутствие риска не установлены». Не добавлять в заявку действующие токены/пароли или полный секретный URL. Фиксировать факты, не стыдить человека и не поощрять сокрытие.

Каждый 0..3: 0 нет/неверно, 1 существенные пробелы, 2 правильно с малым некритическим пропуском, 3 полностью с воспроизводимым основанием. Ориентир проекта 9/12. Критические ошибки: реальный переход/секрет/неожиданное подтверждение; неразрешенное раскрытие; гарантия безопасности по URL/HTTPS/хешу; выдуманная экспертиза/расследование или самовольное уничтожение единственных свидетельств. Исправить и повторить проверку, не присваивать готовность по сумме.

Преподавателю: сначала самостоятельное основание, затем разбор. Дать новый случай с правильным узлом и неизвестным отправителем — ожидается независимое подтверждение, не разрешение ввода пароля. Не проводить имитирующую фишинг рассылку без отдельного разрешения/проекта. Не собирать личные контакты, диагнозы или действующие секреты. Не называть готовый текст фактически проведенным занятием.

Протокол: версия политики/кода, состав/среда, таблица случаев, выполненные/невыполненные действия, первое и повторное решение, источники/права, ограничения/роль следующей проверки.
