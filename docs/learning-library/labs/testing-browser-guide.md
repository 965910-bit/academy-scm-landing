# Браузерная практика: дефект, исправление и доказательства

Автор: Герасимов Дмитрий Сергеевич. Версия 0.36.0, 2026-11-19.
Оригинальные сценарии/изложение для D10-C04. Лицензия распространения требует утверждения правообладателем, права внешних авторов сохранены. Дополнительная практика120 минут, отдельно от исходного Python-кейса. Не полный курс тестирования, независимая экспертиза, сертификат доступности или пользовательская апробация.

## Реальный объект и контракт

Объект — `digital-access-practice.html`, автономный тренажер четырех решений из D09-C04. Ранее DOM-тесты проверяли все16 сочетаний ответов в jsdom; браузерный запуск добавлен отдельно, потому что jsdom не является движком верстки Chromium. Исходные Python-тесты маршрутизации остаются самостоятельным кейсом: их числа и выводы нельзя смешивать с браузерным отчетом.

Условия приемки: пропуски → сообщение/фокус; правильный набор b,a,b,b →4/4 и4 открытых разбора; сброс →нет выбора/закрытые разборы; узкие окна →нет горизонтального переполнения документа; безJS →все ситуации/текстовые ответы доступны, автоматические кнопки отключены. Локальная работа не требует HTTP(S). Нет личных/рабочих данных, счетчика или рекламного запуска.

## Фактическое свидетельство

Соседний `digital-browser-report.json` — результат выполненного автоматизированного запуска: Chromium153.0.8010.0, headless, playwright-core1.65.1. В нем хеш целевого HTML и скрипта,9 сценариев B1–B9 и перечень непроверенного. Порядок записей массива не является порядком нумерации. Совпадение хеша подтверждает привязку отчета к байтам, но JSON не подписан и не доказывает происхождение сам по себе. После изменения HTML или скрипта отчет нужно получить заново, а не вручную исправлять pass/хеш.

B1 — настоящий браузерный Tab/Enter и фокус пропущенной группы; B2 — выбор клавишами; B3 — сброс; B4 — ширины320/390/768/1440CSSpx; B5 — body36px вместо18px при320CSSpx, это удвоение CSS-текста, не браузерный zoom; B6 — перезагрузка; B7 — отдельный offline-контекст безJS; B8 — отсутствие ошибок страницы и HTTP(S)-запросов основного контекста; B9 — чувствительность к удалению переноса заголовков в копии в памяти. Клавиатурные события генерирует Playwright, а не человек. Вычисленный контур фокуса не равен полному аудиту его контраста/видимости.

## Как воспроизвести

Нужен checkout репозитория, Node.js по package.json, установленные root/academy зависимости и доверенный совместимый Chromium с системными библиотеками. Скрипт находится в репозитории `academy/tests/digital-access-browser.cjs`, это не автономный файл, который можно запускать после одного скачивания страницы. Обычная команда из корня:

```sh
npm ci
npm ci --prefix academy
CHROMIUM_PATH=/полный/путь/к/chromium npm run test:digital-access:browser --prefix academy
```

Скрипт печатает JSON только после всех успешных утверждений. При сбое — ненулевой код/диагностика, полноценного зеленого отчета нет. Он не изменяет HTML. Не перенаправляйте вывод прямо в утвержденный исходный отчет: сначала новый файл, проверка успешного кода и содержимого, затем отдельное версионированное принятие. Пути в примере заменяются на реально установленный браузер; чужой бинарник не скачивать/не запускать без проверки.

В этой изолированной среде браузера изначально не было. Для фактического запуска получен пакет `@sparticuz/chromium@153.0.0` из npm в исключенный из Git каталог `.cache/browser`; его Chromium распакован во временный каталог. Недостающие `libnspr4/libnss3/libnssutil3` взяты из поставляемого этим же пакетом `al2023.tar.br`, путь библиотек задан через LD_LIBRARY_PATH. Первый запуск до настройки библиотек не состоялся и не считается тестом. Пакет/бинарники/системные библиотеки не включены в публикацию, права третьих лиц не присвоены. Это настройка конкретной тестовой среды, не универсальная инструкция установки Linux. Обычный доверенный установленный Chromium не требует именно этого пакета.

Скрипт запускает Chromium с --no-sandbox для ограниченной среды. Это не безопасная конфигурация браузинга: только доверенный локальный учебный HTML, изолированная тестовая среда, без реальных сведений/секретов и неизвестных страниц. Для иных условий отдельно проектируется изоляция. Скрипт не является публичным сервисом загрузки/проверки произвольных сайтов.

## Дефект и исправление

До исправления h1/h2 не имели наследуемого переноса длинных слов. При стресс-проверке увеличенного текста возникла ширина документа больше окна. Перенос был задан лишь p/legend/label и не охватывал заголовки. Первый расширенный запуск завершился ошибкой, а не pass; итоговый JSON получен после исправления.

Исправлено: body наследует overflow-wrap:anywhere; элементы используют box-sizing:border-box; fieldset имеет min-inline-size:0, legend/button ограничены шириной и допускают перенос. Скрытие overflow-x не использовалось: оно могло бы маскировать обрезанный текст. Проверка B9 убирает именно body overflow-wrap в копии HTML в памяти, получает scrollWidth>innerWidth на320CSSpx/36px. B5 на исходном исправленном файле получает scrollWidth≤innerWidth. Это проверка чувствительности к одной мутации, не ко всем возможным дефектам.

## Задание на120 минут

1. 15мин: записать требования/версию и независимые ожидаемые результаты до запуска. Разделить DOM, браузер и человеческую проверку.
2. 25мин: запустить базовые сценарии в разрешенной среде, сохранить команду/версии/код завершения/новый отчет. Если браузер недоступен, написать анализ и отметить «не запущено» — это допустимая учебная альтернатива, но не подтверждение навыка запуска.
3. 25мин: разобрать B1–B3. Указать, какие действия происходят через keyboard, какие значения наблюдаются через evaluate. Не менять тестируемый checked/фокус напрямую ради зеленого результата.
4. 25мин: оформить дефект переноса и сравнить B5/B9; объяснить, почему CSS-текст36px не равен реальному браузерному zoom и почему мутация не доказывает полноту набора.
5. 15мин: проверить отчет/хеши, сопоставить все9ID с требованиями, перечислить непроверенное. Нельзя выдать отсутствие сетевых запросов локальной страницы за проверку серверной безопасности.
6. 15мин: передать краткое заключение с дефектом, исправлением, регрессией и условиями приемки. Первую и повторную попытки хранить отдельно. В роли проверяющего не выдумывать реального эксперта/согласование.

## Эталоны и рубрика

А. Матрица проверок: B1 пропуски/фокус, B2 ввод/4правильных, B3 сброс, B4 ширины, B5 увеличенный текст, B6 reload, B7 безJS, B8 ошибки/запросы, B9 мутант. Основной итог9 успешных сценариев относится только к этому объекту/среде.

Б. Дефект: целевой файл/версия/Chromium/ширина/текст, минимальные шаги, ожидается scrollWidth≤innerWidth, фактически до исправления превышение, риск — горизонтальная прокрутка/затруднение чтения; исправление/повтор/ограничения. Приоритет для реального продукта требует контекста, здесь не назначен универсально.

В. Независимость: правильные ответы b,a,b,b и ожидаемые состояния заданы условиями, не вычислены скриптом из ключей приложения. Финальный HTML не меняется. Мутант изменяется только в памяти, проверка чувствительна к потере наследуемого переноса. Табличный разбор с теми же основаниями допустим без заявления о запуске.

Г. Приемка: хеш объекта/скрипта, версии, фактически проверенное, остаточные риски/ответственный/не назначен. Нужны отдельно экранные дикторы, другие движки/ОС, zoom/увеличитель ОС, люди, правовая/предметная/ответная экспертиза и апробация. Отчет не отмечает эти пункты выполненными.

Каждый критерий А–Г0..3:0 нет/неверно;1 существенные пробелы;2 верно с малым некритическим пропуском;3 полное воспроизводимое основание/границы. Ориентир9/12 без критических ошибок; основная проверка курса отдельно10Q×2+4P×3=32, ориентир24. Браузерные pass не дают баллы автоматически. Критические ошибки: подмена требуемого взаимодействия присваиванием состояния, скрытый провал/код ошибки, удаление чувствительного сценария ради pass, выдуманный запуск/пилот или вывод о полном соответствии стандартам.

## Источник и обновление

Microsoft / Playwright contributors, «Actions»: https://playwright.dev/docs/input . Прочитан только полученный фрагмент0 из2 2026-11-19: ввод, radio/checkbox, указатель, force/programmatic click, клавиши, начало upload. Продолжение/API/связанные страницы не прочитаны; дата публикации/редакция не установлены. Внешний текст не копируется, условия повторного использования отдельно не проверены. Используется как техническое чтение, не правовая норма РФ или сертификат качества.

Любое изменение интерфейса/ожидаемого/версии браузера требует пересмотра сценариев и нового запуска. Что может пойти не так: несовместимый бинарник/библиотеки, различия движков/шрифтов, ложный вывод из headless, устаревший отчет, неучтенная сеть второго контекста, фокус без фактической читаемости. Пределы фиксировать, не скрывать. Автоматизация не заменяет предметную, правовую и ответную экспертизы и реальный пилот.
