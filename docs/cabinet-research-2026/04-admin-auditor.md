# 04. Администратор и аудитор

Дата: 19.11.2026. Источники S11, S14, S16–S19 раскрыты в [реестре](00-overview.md#6-реестр-источников-и-глубина-чтения). Предлагаемые права сотрудников не меняют запрошенный владельцем полный доступ к реализованным инструментам.

## 1. Кабинет администратора Академии

**Подтверждено.** TalentLMS описывает Administrator, Instructor, Learner и настраиваемые user types; профиль может сочетать права, а смена типа способна повлиять на старые назначения [S16]. Branches выделяет пользователей, каталоги, отчёты и область администратора; изменение общего курса распространяется на связанные области [S17]. Moodle Workplace добавляет программы, правила назначений, отчёты и сертификаты [S11]. Наличие таких продуктов не отменяет необходимости собственной предметной модели.

| Адаптация Академии | Ручной ввод, поиск и фильтры | Данные и зависимости | Приёмка |
|---|---|---|---|
| P0 Люди и назначения | Создать/исправить профиль, назначить роль и область; ФИО/ID/роль/статус | User, membership, role grant, audit | Два человека с одинаковым ФИО не смешиваются; смена права не удаляет историю |
| P0 Программы и направления | Карточки всех семи линий, активация после оснований | Program version, license/evidence, publication flags | Неактивная линия подготовлена, но не выдаётся за лицензированный набор |
| P0 Зачисления и потоки | Назначить, перевести, завершить с основанием | Enrollment, cohort, transitions | Повтор команды не создаёт второе зачисление |
| P1 Расписание | Занятие, аудитория, преподаватель; дата/поток/формат | Sessions, capacity, ресурсы | Одновременные брони не конфликтуют молча |
| P1 Документы и выдача | Проект, проверка, выпуск, отзыв; тип/номер/эмитент/статус | Credential, template version, human approval | Выдача имеет человека, основание и версию; печать не равна подписи |
| P1 Импорт и экспорт | CSV/пакетный ввод, сопоставление колонок | Import job, staging, ошибки строк | Предпросмотр, проверка дублей, частичный результат, безопасный повтор |
| P1 Договоры и расчёты | Счёт, запрос сверки, ручная корректировка с основанием | Организация, договор, invoice/payment | Ручной статус отделён от подтверждения платёжного оператора |
| P1 Отчётность | Сохранённые отчёты, расписание отправки | Источники, условия, аудитории | Один и тот же пользователь не расширяет область через отчёт |
| P2 Автоматизация | Правила назначения, напоминания, пакетные операции | Event/outbox, idempotency, execution log | Тестовый прогон показывает точный список изменений; цикл правил останавливается |
| P2 Интеграции | Настройки провайдера, состояние очереди, повтор ошибки | Секреты на сервере, API adapter, reconciliation | Ключи не видны в браузере; повтор не удваивает выдачу/платёж |

**Ручной ввод не второсортный режим.** До интеграции администратор должен иметь понятный маршрут внесения реального факта с указанием источника. Но отметка сотрудника и подтверждение внешнего реестра остаются разными доказательствами. Исправление — событие с причиной, а не бесследное изменение прошлого.

**Архитектурная цена:** нормализованные сущности вместо разрозненных JSON-копий; транзакции; журнал изменений; резервное копирование с проверкой восстановления; фоновые задания; обработка ошибок. Report builder [S14] показывает, что фильтр пользователя и обязательное условие доступа — разные вещи. Пользовательский фильтр можно снять; условие области организации — нельзя.

**Текущий код:** admin, локальный вход владельца по ФИО без пароля, управление учётными записями, ручные журналы, документы и билет существуют. Это не заявление о готовности всех перечисленных предметных операций и не доказательство исправления `scm-news.online`. Настройку владельца данной серией не меняем.

### Что здесь может пойти не так

- Полномочия дадут видимость кнопок, но не рабочий серверный путь.
- Смена типа пользователя удалит действующие учебные назначения.
- Импорт перезапишет ФИО или документ из-за неверного сопоставления колонок.
- Правило автоматизации запустит само себя и создаст дубли/расходы.

## 2. Кабинет аудитора

**Подтверждено.** Canvas Gradebook History — журнал только для чтения, с фильтрами по студенту, проверяющему, объекту и дате; показывает предыдущее, новое и текущее значение, имеет ограничения для анонимного оценивания и описанную глубину 365 дней [S18]. Grade Change Log API описывает события с before/after, grader, student, assignment, версиями/идентификаторами и GET-выборками [S19]. Это доказательство предметного журнала оценок, не готового «универсального аудиторского кабинета».

| Адаптация Академии | Ручной ввод, поиск и фильтры | Данные и зависимости | Приёмка |
|---|---|---|---|
| P0 Журнал изменений | ФИО/actor/объект/дата/действие; сохранить выборку | Audit event, correlation ID, scope | Нельзя менять проверяемые данные через этот контур; неуспешный доступ тоже фиксируется |
| P1 История оценки | Сравнение before/after, причина, критерии | Grade versions, rubric, submission | Видна цепочка от работы до опубликованного результата |
| P1 Проверка документа | Номер, эмитент, основание, выдача/отзыв | Credential versions, approval, registry publication | История локальной выдачи не подменяет ответ внешнего реестра |
| P1 Проверка доступа | Кто получил/утратил право, в какой организации | Role grants, membership history | Можно восстановить область права на момент события |
| P1 Материалы проверки | Замечание, подтверждение, ответ ответственного | Audit case, evidence, workflow | Заметка аудитора не редактирует исходную оценку или приказ |
| P1 Выгрузка доказательств | Период/область/тип, манифест файлов | Export job, hashes, scope, срок ссылки | Есть автор, время и состав; хеш доказывает целостность копии, не истинность решения |
| P2 Контроль полноты | Разрывы цепочек, аномалии, сверки | Модель ожидаемых событий и reconciliation | Утрата события обнаруживается; не просто красивый лог имеющихся строк |

Аудитор может вносить **свои замечания и рабочие материалы**, но не менять факты проверки. Исправление факта идёт через уполномоченного сотрудника и оставляет новое событие. Для внутреннего и внешнего аудитора нужны разные области и срок доступа; это **адаптация**, подлежащая согласованию с регламентом.

**Архитектурная цена:** единая схема событий; синхронизированное время; хранение с политикой сроков; защита от незаметного редактирования; независимые резервные копии; выгрузки и расследования. Таблица `audit` в одной базе под тем же полным администратором сама по себе не обеспечивает неоспоримость. Криптографическая цепочка или внешнее хранилище повышают проверяемость, но требуют ключей, мониторинга и процедуры восстановления. Ни один референс не доказывает автоматического юридического статуса такого журнала.

**Текущий код:** серверный аудит отдельных действий есть; отдельной роли auditor, полной истории оценок и защищённого evidence-пакета нет. Canvas используется как функциональный образец, не заявленная интеграция.

### Что здесь может пойти не так

- Журнал начнёт хранить пароли, токены и лишние персональные данные.
- Отсутствие события будет ошибочно прочитано как отсутствие действия.
- Системный администратор сможет незаметно править и исходные данные, и журнал.
- Выгрузка доказательств обойдёт ограничения карточки пользователя.

## 3. Проверка управляемости

Внести изменение оценки с основанием, затем отозвать право автора и открыть историю аудитором. Старый автор и его прежняя область должны оставаться восстанавливаемыми. Затем восстановить резервную копию в изолированной среде и сравнить цепочку. Проверить поддельный идентификатор объекта в URL и экспорте. Для внешней проверки выдать временный доступ только к согласованному набору записей и проверить его окончание.

### Что здесь может пойти не так

- Резервная копия существует, но восстановление никогда не пробовали.
- Удаление сотрудника уничтожит имя автора прошлых решений.
- Срок доступа закончится в интерфейсе, но старая ссылка на файл останется доступной.
