# Внедрение исследования: фактический статус

19.11.2026. Этот файл обновляет исходный срез исследования, но не означает завершения всех функций из шести документов.

## Уже работает в этой ветке

- Десять типов учётных записей, создание четырёх новых ролей и открытие их кабинетов администратором. Вход владельца по ФИО без пароля сохранён.
- Рабочий центр для всех ролей: ручное создание, поиск, статус, диапазон дат, сброс, сохранённый фильтр на устройстве, пагинация по 20 записей, JSON-экспорт доступного набора.
- Общая заявка: черновик → подана → исправления → проверена → зачислена / отказ / отзыв. Исправление сохраняет предыдущую версию. Подтверждение зачисления создаёт отдельное учебное назначение без удаления роли абитуриента.
- Задание: назначение конкретному человеку, текстовый ответ, возврат, повтор, принятие преподавателем с комментарием. Это не балльная ведомость и не файловая сдача.
- Сопровождение: обращения, ответственный, обсуждение, решение и закрытие.
- Расписание: запись с датой и одним назначенным участником, подтверждение/отмена участия, завершение/отмена занятия. Это ещё не групповой календарь со слотами, временем начала, вместимостью и контролем пересечений.
- Внутренние подтверждения: проект, выдача человеком, отзыв. Это предметная запись; автоматическая связь с существующим ID-бейджем, шаблоном PDF или опубликованным реестром пока не сделана.
- CPD: текстовая активность выпускника, подача, запрос уточнений, подтверждение Академией. Баллы внешнего эмитента не начисляются.
- Вакансии: проект работодателя, модерация, публикация выпускникам/слушателям, закрытие. Публичное представление исключает внутренние комментарии, идентификаторы авторов и историю модерации. Отклики пока через контакт из текста, не отдельная система резюме.
- Корпоративный запрос: программа, цель, срок и согласование с Академией. Работодатель пока не импортирует команду и не назначает ей обучение самостоятельно.
- Справочник организаций и очередь платформенных работ/инцидентов. Они не создают отдельную изолированную академию и не являются техническим мониторингом.
- Аудитор читает доступные предметные записи, события и выгрузку; команды изменения отклоняются движком и сервером. В этой первой одноконтурной модели аудитор видит всю Академию; временные внешние аудиторы и выборочные области ещё не реализованы.

В переписке рабочего центра нет скрытых внутренних заметок: содержимое доступно участникам записи. Для конфиденциального экспертного заключения нужен отдельный тип данных и политика видимости.

## Два разных режима сохранения

**Браузер владельца:** `scm-academy-shared-workflows-v1` — общий журнал локальных профилей на одном устройстве. Профиль пользователя и личные учебные инструменты остаются в прежних отдельных пространствах. Локальный режим не является серверной авторизацией или защищённым архивом персональных данных. Очистка хранилища удаляет журнал. Экспорт личного рабочего пространства не включает этот общий журнал: используйте отдельную кнопку экспорта в Рабочем центре. Локальное одновременное сохранение использует Web Locks при доступности API; без него гарантии межвкладочной транзакции нет.

**Node-сервер:** `/api/workflows` GET/POST; отдельная таблица `workflow_store` в существующей SQLite. Сессия, права, допустимые переходы, автор, область видимости и повтор команды проверяются на сервере. Запись проходит в транзакции вместе с серверным аудитом. Сохраняется идентификатор администратора, если он открыл кабинет другого человека. Конфликт общей ревизии возвращает 409 без перезаписи; текст не очищается при ошибке.

Таблица хранит версионированный общий агрегат JSON. Это первый общий контур вместо независимых копий; это **не** нормализованная многотенантная LMS из целевой архитектуры. По мере роста нужны предметные таблицы, индексы, отдельные области и миграции. История в той же SQLite не является защищённым от администратора внешним журналом. Идемпотентность работает при повторе команды с тем же ключом; после сетевой ошибки новый пользовательский запуск создаёт новый ключ, поэтому автоматический повтор не выполняется.

Оффлайн доступны закэшированная оболочка и локальный журнал. Серверные приватные ответы не добавляются в service worker. Оффлайн-очередь серверных команд и синхронизация частных курсов пока не реализованы.

| Область | Следующие предметные функции |
|---|---|
| Приём | Версионированные файлы и checklist, защищённое хранилище, комиссия с внутренними заметками, места/конкурс, слоты собеседований |
| Обучение | Версии курсов и рубрик, балльная ведомость, файловые работы, пересдачи, апелляции, частная оффлайн-синхронизация |

| Компании | Членства, оргструктура, импорт команды, места, договоры, счета, командная отчётность и HR-сверка |
| Управление | Пакетный импорт, общая активация программ, предметные отчёты, согласования, уведомления, проверенные резервные восстановления |
| Платформа | Изоляция tenant, технические метрики, очереди, управление секретами, миграции, техническая защита журнала |
| Внешние поставщики | Оплата, ЭДО/подпись, email/SMS, видеосервис, прокторинг, СКУД, внешний реестр, ASCM — не подключены |
| ИИ | Не подключён: сначала разрешённые данные, эталонные задачи, лимиты расходов и контроль человека |

## Проверки

- `npm test --prefix academy`: 105/105 — существующие и новые тесты движка, HTTP и интерфейса.
- `npm run test:browser --prefix academy`: регрессия реального серверного входа, учётных записей, сохранения и выхода.
- `node academy/tests/shared-workflows-browser.cjs`: вход владельца без пароля, девять профилей, общий приём/зачисление, аудит без изменения, интерфейсы десяти ролей на ширинах 320/390/768/1440.
- Chromium-запуски требуют `CHROMIUM_PATH` и системных библиотек. Успешная проверка браузера в sandbox не заменяет тестирование опубликованного домена.

## Что здесь может пойти не так

- Новые минимальные процессы будут приняты за полное внедрение всех референсных продуктов.
- Два локальных браузера будут ошибочно восприняты как общий сервер.
- Одноконтурный JSON-агрегат станет узким местом без последующей предметной миграции.
- Записи о документах и инцидентах будут названы подключённым реестром или мониторингом.
