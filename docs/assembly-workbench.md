# Сборочная мастерская

## Режим работы по решению владельца

Система собирается целиком для проверки сценариев. Единый сервер, промышленная защита и последующее распределение полномочий — отдельный этап, который определяет владелец. Эти вопросы не служат основанием скрывать модули сборки. Существующий Рабочий центр с серверным API сохранён; мастерская его не заменяет.

В любом из десяти кабинетов добавлен пункт **«Сборка · все разделы»**. В этом пространстве доступны все 28 разделов без проверки роли. Данные мастерской общие для профилей текущего браузера и не требуют соединения с сервером. Вход владельца по ФИО без пароля не изменён.

## Что можно проверить сейчас

28 разделов: комплект приёмных документов, собеседования, комиссия, потоки/группы, версии материалов, ведомость/рубрики, апелляции/пересдачи, расписание/ресурсы, посещаемость, архив выпускника, профессиональные профили, обсуждения, наставничество, мероприятия, резюме/отклики, CPD, компании/команды, корпоративные назначения, договоры/акты, счета/сверка, выдача/отзыв документов, отчёты, исходящая очередь, аудиторские проверки, конфигурации академий, поставщики интеграций, эксплуатационные проверки и задачи ИИ.

Во всех разделах работают предметные поля, собственные статусы, создание, исправление, копирование, удаление, поиск/фильтр статуса, вложения, скачивание, история предыдущих данных, общий экспорт и объединяющий импорт JSON. Одинаковый ID при импорте не перезаписывает существующую запись. Можно проверить ручной сквозной сценарий, связывая записи по номеру в поле основания/ссылки.

Дополнительные вычисления:
- Рубрика `критерий; баллы; максимум` по строкам: сумма и процент, проверка допустимых баллов.
- Расписание: пересечения по преподавателю или ресурсу на основании даты, времени и длительности.
- Группы/мероприятия/заказы: число участников относительно указанного количества мест.
- ИИ: расчёт стоимости по введённым токенам и тарифу за 1000 токенов.

Это **работающие ручные инструменты сборки**, а не заявление, что специализированная автоматизация всех функций исследования уже закончена. Например, отчёт пока является заполняемой карточкой с файлами, а не произвольным SQL-конструктором; запись академии не создаёт изолированный tenant; карточка резервной копии не запускает восстановление сервера. Профиль с «не публиковать» не уходит в публичный каталог — публичной публикации из мастерской пока нет.

## Хранение и внешние сервисы

Ключ `scm-academy-assembly-v1`, отдельный от прежнего общего журнала и личных рабочих пространств. Экспорт мастерской включает вложения и историю. Квота браузера определяется устройством; ошибка записи не должна сообщать об успехе. Импорт сначала проверяется в памяти и только потом записывается.

Карточки поставщиков позволяют собрать адреса и параметры будущих подключений без хранения секретов в полях. Они **не выполняют внешние API-вызовы**. Статусы внешних ответов подписаны как внесённые вручную; локальная отметка не объявляется банковским платежом, подписью, внешним сертификатом или вызовом модели. Это фактическое состояние реализации, а не отказ от подключения этих сервисов в дальнейшем.
